# Iteration 008 - Status Granularity Broadening

日期：2026-06-25

## 本轮目标

继续优化每日打卡中的“状态”维度，把过细的具体事项合并为更宽泛的日常活动状态。

## 用户反馈

上一版中：

- “吃饭、喝咖啡、做饭”太细，可以合并成“美食”。
- “睡觉”可以保留。
- “拉伸”太细，本质是健身里的小项目，不应该占一个主状态位。

本轮目标是让 24 个状态覆盖绝大多数人的每日活动，同时避免变成具体事项清单。

## 新筛选原则

1. 状态词要覆盖一类活动，而不是一个具体动作。
2. 具体事项能合并就合并，例如吃饭、做饭、喝咖啡合并为“美食”。
3. 子项目不占主状态位，例如拉伸不单列。
4. 保持 24 个总量。
5. 仍然要短、轻、好图标化。

## 相比上一版的调整

| 旧状态 | 新处理 | 原因 |
| --- | --- | --- |
| 吃饭 | 合并为美食 | 具体事项，适合归入更宽泛的生活状态 |
| 喝咖啡 | 合并为美食 | 太具体，不占主状态位 |
| 做饭 | 合并为美食 | 与吃饭同属饮食生活 |
| 拉伸 | 删除 | 属于健身/运动子项目 |
| 散步 | 合并为户外 | 更宽泛，可覆盖散步、晒太阳、逛公园等 |
| 新增家务 | 保留为主状态 | 覆盖清洁、整理、洗衣等生活事务 |
| 新增购物 | 保留为主状态 | 覆盖逛街、超市、买东西等日常场景 |
| 新增养生 | 保留为主状态 | 覆盖健康管理、放松护理、身体照顾等 |

## 当前推荐结论

本轮版本比 Iteration 007 更适合作为状态 V1：

- 颗粒度更统一。
- 生活覆盖面更宽。
- 具体行为不再挤占主状态位。
- 更适合做 24 个统一图标。
