# Iteration 011 - Mood Diary Multi Moment Records And Daily Trajectory

日期：2026-07-12

## 背景

用户希望心情日记从“一天只能记录一次今日心情”升级为“一天可以记录多次此刻心情”。每次记录需要保存当前时刻，用户可以在当天看到心情变化，并在日历中回看某一天的心情轨迹。

同时，用户希望新增“每日回顾”：用户可选择是否完成一次当天整体回顾，回顾时也需要选择一个心情图标。心情日历中如果某天有普通记录，则当天打勾；如果完成整体回顾，则当天显示整体回顾图标；点击有记录的日期进入当天心情轨迹。

## 核心产品判断

本次不应只把“今日心情记录”改成允许多次提交。更合理的产品结构是：

```text
此刻心情记录：一天可多次，记录即时状态。
每日回顾：一天最多一次，代表当天整体感受。
今日心情轨迹：把当天多次记录串成变化过程。
心情日历：按日期展示是否有记录，以及是否完成每日回顾。
```

这样可以同时解决三个问题：

- 用户想随时记录，而不是被“一天一次”限制。
- 产品仍然有一个代表当天的总结状态，方便日历和分析使用。
- 用户能看到情绪不是一个点，而是一条变化线。

## 此刻心情记录页

当前 `pkgDailyCheckin/record` 页面可以作为基础，但需改为“创建一条新记录”，不再按日期进入编辑单条当天记录。

### 页面标题

- 新建：记录此刻心情
- 查看：回看此刻心情
- 编辑：修改此刻心情

### Hero 文案

```text
此刻的你，感觉如何？
```

副文案：

```text
把现在这一刻轻轻记下来。
```

### 时间记录

在小记忆区域显示时间 chip：

```text
今天 HH:mm
```

规则：

- 默认使用系统当前时间。
- 后端以服务器时间为准保存 `recorded_at`。
- 前端展示本地格式化后的 HH:mm。
- MVP 不提供手动修改时间，避免补记和真实时间混淆。

### 字段

沿用现有三维度：

- 心情：必选 1 个。
- 状态：必选 1-3 个。
- 颜色：必选 1 个。
- 小记忆：选填。
- 照片：选填，最多 3 张。
- 位置：选填。

### 提交按钮

```text
保存此刻心情
```

提交后返回心情日记首页或今日轨迹页，建议默认返回首页，并刷新“今日心情轨迹”。

## 今日心情轨迹页

新增页面，建议路径：

```text
AImental_frontend/pkgDailyCheckin/trajectory/
```

支持参数：

```text
/pkgDailyCheckin/trajectory?date=YYYY-MM-DD
```

如果不传 date，默认今天。

### 顶部区域

展示日期：

```text
7月12日 周日
```

右侧可有按钮：

```text
记录此刻
```

仅当 date 是今天时展示；历史日期不展示或置灰。

### 顶部心情图标序列

位于页面最上方，依次显示当天记录的心情图标。

规则：

- 按时间从早到晚排列。
- 每个图标下方显示 HH:mm。
- 如果记录超过 8 条，横向滚动。
- 如果当天有每日回顾，在最后额外显示一个“回顾”节点，样式和普通节点区分。

### 心情变化记录

建议名称：

```text
心情变化
```

推荐视觉：时间轴 + 心情流动线。

每条记录是一张时间节点卡：

- 左侧：时间 HH:mm
- 中间：心情图标 + 心情名称
- 右侧：颜色点 / 状态标签
- 下方：小记忆摘要，最多 2 行
- 图片缩略图如有则展示

节点之间用一条细线连接，形成一天的心情流动。

### 情绪流动提示

在时间轴上方放一条短解释：

```text
今天的心情并不是固定的一种，它在不同时间里轻轻变化。
```

如果当天记录数 >= 2，可以根据第一条和最后一条生成一句趋势文案：

- 从低能量到高能量：今天像是慢慢亮起来了。
- 从高能量到低能量：今天后半段可能有些消耗。
- 起伏明显：今天的情绪有一些波动。
- 相对平稳：今天的状态整体比较稳定。

该文案 V1 可前端简单生成，后续可交给 AI。

## 每日回顾

每日回顾是当天整体总结，不是普通此刻记录。

### 入口位置

在今日心情轨迹页底部展示。

如果今天未完成回顾：

```text
完成今日回顾
```

副文案：

```text
用一个心情图标，总结今天整体的感觉。
```

如果今天已完成回顾：

- 展示回顾卡。
- 显示回顾图标。
- 显示回顾文字。
- 提供“修改回顾”入口。

### 回顾流程

推荐问题：

1. 今天整体更像哪种心情？
   - 使用现有 24 个心情图标。
   - 必选 1 个。

2. 今天整体状态如何？
   - 可复用状态标签，最多 3 个。
   - P0 可选，P1 再做。

3. 给今天留一句话。
   - 选填。
   - placeholder：如果用一句话总结今天，你会怎么说？

4. 明天想怎样照顾自己？
   - 选填。
   - placeholder：给明天的自己一点小小提醒。

### 回顾结果

回顾完成后：

- 心情轨迹页底部显示回顾卡。
- 心情日历该日期显示回顾图标。
- 今日心情轨迹图标序列最后显示一个“回顾”节点。

## 心情日历改造

当前日历按月显示，且某天只有一条记录。新版本需要支持：

- 按年 / 月切换。
- 点击某一天。
- 展示这一天是否有此刻记录。
- 展示这一天是否有每日回顾。

### 日期格展示规则

1. 无记录、无回顾：
   - 显示日期数字。

2. 有此刻记录、无回顾：
   - 日期上打勾。
   - 可加一个小数字，如 `3` 表示记录 3 次。
   - 不显示某个心情图标，避免用某一次记录代表整天。

3. 有每日回顾：
   - 显示每日回顾选择的心情图标。
   - 同时可保留小勾或小点，表示当天也有记录。
   - 图标优先级高于普通勾。

4. 今天：
   - 保留“今天”描边或高亮。

### 点击日期

点击有此刻记录或有每日回顾的日期：

```text
进入 /pkgDailyCheckin/trajectory?date=YYYY-MM-DD
```

点击无记录日期：

- 如果是今天：提示或直接进入记录此刻心情。
- 如果是过去日期：提示“这一天还没有心情记录”。

### 月份 / 年份切换

当前已有左右切换月份。

建议增强：

- 保留左右切换。
- 增加当前年月标题点击后打开年月选择器。
- 增加“回到今天”按钮。

## 数据模型建议

### 推荐方案：扩展现有 checkins 表

为了减少改造成本，建议先扩展现有 `checkins` 表，而不是立刻新建多张表。

新增字段：

```text
record_type: moment | daily_review
record_date: YYYY-MM-DD
recorded_at: timestamp
local_time: HH:mm
review_note: 每日回顾一句话，可选
tomorrow_note: 给明天的小提醒，可选
```

解释：

- `moment`：此刻心情记录，一天多条。
- `daily_review`：每日回顾，一天最多一条。
- `timestamp` 可继续使用，但语义明确为记录发生时间。
- `record_date` 用于按本地日期查询，避免只靠 `strftime` 造成时区问题。

### 兼容旧数据

旧的每日打卡记录迁移为：

```text
record_type = moment
record_date = 旧 timestamp 对应日期
recorded_at = 旧 timestamp
```

旧数据在日历中表现为：

- 有记录，显示勾。
- 没有每日回顾图标。

## API 建议

### 创建此刻记录

```text
POST /api/v1/checkin/moments
```

行为：

- 不再判断“今天是否已有记录”。
- 每次提交都创建新记录。
- 后端自动写入 `record_type=moment`、`recorded_at`、`record_date`。

### 获取某日心情轨迹

```text
GET /api/v1/checkin/date/{date}/timeline
```

返回：

```json
{
  "date": "2026-07-12",
  "moments": [],
  "daily_review": null,
  "summary": {
    "moment_count": 3,
    "has_review": false,
    "first_mood": "平静",
    "last_mood": "疲惫"
  }
}
```

### 创建或更新每日回顾

```text
PUT /api/v1/checkin/date/{date}/review
```

规则：

- 每天最多一条 daily_review。
- 再次提交为更新。

### 获取月历汇总

```text
GET /api/v1/checkin/month/{year}/{month}
```

新返回建议：

```json
{
  "12": {
    "date": "2026-07-12",
    "has_moments": true,
    "moment_count": 4,
    "has_review": true,
    "review_mood_id": "calm",
    "review_mood_icon": "calm",
    "latest_mood_id": "tired"
  }
}
```

前端用：

- `has_moments` 决定是否打勾。
- `moment_count` 决定是否显示次数。
- `has_review` 和 `review_mood_icon` 决定是否显示整体回顾图标。

### 兼容接口

现有接口：

```text
GET /api/v1/checkin/date/{date}
```

建议短期保留，返回当天最近一条 moment 或旧数据，避免旧页面崩溃。

## 后端改造重点

1. 移除创建接口中“一天只能一条”的 409 限制。
2. 增加 `record_type`，区分此刻记录和每日回顾。
3. 支持按日期返回多条 moment。
4. 支持每日回顾一天最多一条。
5. 月历接口改成按天聚合，不再只返回某天一条 checkin。
6. 旧数据兼容。
7. 图片接口继续复用现有多图能力。

## 分阶段落地

### P0：完成核心闭环

- 一天可创建多条此刻心情记录。
- 首页新增今日心情轨迹预览。
- 新增今日心情轨迹页。
- 新增每日回顾，一天最多一次。
- 日历有记录打勾，有回顾显示图标。
- 点击日历日期进入当天轨迹。

### P1：增强体验

- 心情轨迹页增加趋势文案。
- 支持编辑 / 删除当天某条此刻记录。
- 每日回顾支持“给明天的小提醒”。
- 日历显示记录次数。
- 首页展示最近 3 条此刻心情。

### P2：分析联动

- 心情分析页接入一天多次记录。
- 周报/月报区分“此刻记录”和“每日回顾”。
- AI 根据一天内心情变化生成简短回顾。
- 支持补记历史某一时刻。

## 验收标准

- 用户一天内可以保存多条心情记录。
- 每条记录都保存具体时间，并能在轨迹页显示 HH:mm。
- 心情日记首页主入口文案已从“今日心情”改为“此刻心情”。
- 心情日记首页底部有“今日心情轨迹”模块和入口。
- 今日心情轨迹页顶部能按时间顺序展示当天所有心情图标。
- 今日心情轨迹页能展示时间轴式心情变化记录。
- 用户可以完成一次每日回顾并选择一个心情图标。
- 每日回顾完成后，日历对应日期显示回顾图标。
- 只有普通此刻记录、没有回顾时，日历对应日期显示勾。
- 点击日历中有记录的日期，进入当天心情轨迹页。
- 旧的历史记录不丢失，并能以普通此刻记录出现在轨迹里。

## 风险与注意事项

- 多次记录后，日历不能随便用某一次心情代表全天，否则会误导用户；应优先用每日回顾图标代表当天整体状态。
- 如果没有每日回顾，日历只显示勾，不显示最后一次心情图标。
- 心情分析逻辑需要后续重构，不能再假设一天只有一条记录。
- 轨迹页不要做得像监控报表，要保持“日记感”和“情绪流动感”。
