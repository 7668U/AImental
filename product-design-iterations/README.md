# Product Design Iteration Archive

这个文件夹用于保存本小程序优化升级过程中的产品设计方案、决策记录和待办需求。

## 留档规则

每次我们讨论形成新的设计方案、产品判断或优先级调整时，都需要在这里留档。

主要文件结构：

- `iterations/`：每次方案迭代的完整记录，按日期和序号命名。
- `decision-log.md`：关键产品决策日志，只记录已经确认或阶段性确认的判断。
- `backlog.md`：需求池与后续优化事项，方便后续排期和验收。

## 单次迭代记录模板

每次迭代记录建议包含：

- 背景与目标
- 当前问题或机会
- 用户体验方案
- 功能范围
- 前后端影响
- 数据、风控与隐私注意点
- 验收标准
- 未决问题
- 下一步行动

## 协作原则

1. 先明确用户价值，再决定功能形态。
2. 每个方案都要能落到页面、交互、接口或运营动作上。
3. 心理健康相关能力要谨慎表达，避免过度诊断化承诺。
4. 重要设计判断要沉淀到 `decision-log.md`，避免反复摇摆。
5. 需求进入开发前，需要补齐验收标准和影响范围。
