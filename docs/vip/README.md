## 1. 当前决策

VIP 系统首期设置三个等级，并采用首发体验价：

| 套餐 | 首发体验价 | 计划标准价 | 心情树洞 | 心灵社区 | 单项心情分析 | AI 测评分析 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 轻语会员 | 8.99 元/月 | 17.99 元/月 | 1000 次/月 | 1000 次/月 | 100 次/月 | 100 次/月 |
| 相知会员 | 13.99 元/月 | 27.99 元/月 | 2000 次/月 | 2000 次/月 | 200 次/月 | 200 次/月 |
| 长伴会员 | 18.99 元/月 | 37.99 元/月 | 3000 次/月 | 3000 次/月 | 300 次/月 | 300 次/月 |

套餐定位：

- 轻语会员：面向低频用户，提供低门槛的付费体验。
- 相知会员：面向稳定使用用户，作为默认主推套餐。
- 长伴会员：面向高频用户，提供更充足的长期陪伴额度。

前端展示时建议将相知会员标记为“最受欢迎”。

首发阶段前端统一使用“首发体验价”表述，不使用尚未实际执行过的“原价”“划线价”或“五折”宣传。推广结束后，新购买用户切换至届时正式确认的标准价格。

## 2. 免费用户方案

免费用户每月获得以下权益：

| 权益 | 免费额度 |
| --- | ---: |
| 心情树洞 | 100 次/月 |
| 心灵社区 | 100 次/月 |
| 单项心情分析 | 4 次/月 |
| AI 测评分析 | 4 次/月 |
| 心情记录、心情日历和历史数据 | 免费使用 |
| 基础心理测评、规则评分和基础结果 | 免费使用 |

免费额度按自然月重置，不结转至下个月。免费用户的心情分析额度可以支持每月体验一次四模块完整分析。

## 3. 权益次数定义

### 3.1 对话次数

心情树洞和心灵社区均按照“成功完成的用户回合”计次：

- 用户发送一条消息，系统成功生成并返回 AI 回复，扣除 1 次。
- AI 在一个用户回合中返回多条连续消息，仍只扣除 1 次。
- 模型调用失败、系统异常或消息未成功生成时，不扣除次数。
- 内容安全拦截、输入超限、频率限制或后端风控拦截时，不调用模型且不扣除次数。

### 3.2 单项心情分析

心情分析页面包含以下四个独立 AI 分析模块：

1. 心情分布分析
2. 状态与心情关联分析
3. 日记词云与主题分析
4. 情绪颜色分析

每成功新生成一个模块的 AI 分析文案，扣除 1 次单项心情分析额度。

- 用户只生成其中一个模块时，只扣除 1 次。
- 同一份数据命中已有缓存并直接查看时，不重复扣除次数。
- 用户记录发生变化，导致数据签名变化并重新生成分析时，视为一次新的生成。
- 用户主动要求刷新并实际重新调用模型时，扣除 1 次。

因此，轻语会员的 100 次额度最多可以支持 25 组四模块完整分析，也可以由用户自由分配给不同周期和不同模块。

AI 情绪色卡背景图属于图片模型能力，其额度和成本暂不纳入本方案，后续需要单独确认。

### 3.3 AI 测评分析

AI 测评分析额度只用于实际调用大模型生成的新内容，不用于限制基础测评功能：

- 量表答题、规则评分、结果等级和基础结果解释不扣除 AI 测评分析额度。
- 单份测评结果的新 AI 解读，成功生成后扣除 1 次。
- 多份历史测评的综合分析，成功生成后扣除 1 次。
- 命中相同测评记录组合的缓存、查看历史报告或重复打开结果页时，不重复扣除次数。
- 模型调用失败或报告未成功保存时，不扣除次数。

当前后端部分测评结果中的“AI 分析”由规则生成，并未实际调用大模型；此类结果首期不应扣除额度。后续需要明确哪些量表接入真正的大模型解读，并统一接入额度和成本记录。

### 3.4 功能加量包

免费用户和会员用户都可以根据需要单独购买功能加量包。加量包提供按需付费路径，不要求用户必须先开通会员。

首期设置四种单功能加量包：

| 加量包 | 增加额度 | 首发加量价 | 计划标准价 |
| --- | ---: | ---: | ---: |
| 树洞加量包 | 500 次 | 1.99 元 | 2.99 元 |
| 社区加量包 | 500 次 | 2.99 元 | 3.99 元 |
| 心情分析包 | 50 次 | 0.99 元 | 1.49 元 |
| 测评分析包 | 50 次 | 0.99 元 | 1.49 元 |

加量包定价原则：

- 单项加量包的单位价格高于会员升级后的综合单位价格，避免加量包替代会员体系。
- 轻语会员和相知会员额度不足时，前端优先展示升级套餐，再提供单项加量包。
- 长伴会员无法继续升级时，直接提供对应功能加量包。
- 免费用户可以直接购买加量包，同时展示会员套餐的额度和价格对比，由用户自行选择按需购买或开通会员。
- 社区加量包价格高于其他加量包，因为社区单回合模型成本明显更高。

本轮额度和加量包价格基于新的优惠上游 API 调整。旧版 Pro 模型成本与毛利率估算已失效，正式上线前需要用新上游的真实账单重新核算。

加量包使用规则：

- 加量包为单次购买，不自动续费。
- 每个加量包自购买成功之日起 90 天内有效。
- 加量包不随自然月或会员购买周期重置，也不属于月度额度结转。
- 用户没有有效会员时，仍可在有效期内使用已经购买的加量包。
- 系统按照“最早过期优先”顺序消耗额度。通常先消耗当月免费额度或当前会员周期额度，再消耗 90 天有效的加量包。
- 模型失败、系统异常、内容安全拦截、输入超限和风控拒绝均不扣除加量包次数。
- 缓存命中和查看已有报告不重复扣除加量包次数。
- 同一功能每 30 天最多购买 5 个加量包，超过限制后触发成本预警或人工复核。
- 加量包同样受输入长度、Token、请求频率、并发和异常行为风控限制。

## 4. 首期模型策略

首期所有用户可见的 AI 能力统一使用：

```text
hepai/deepseek-v4-pro
```

首期不为了降低成本提前切换 Flash 模型，原因如下：

- 优先保证心情树洞、心灵社区和分析报告的用户体验。
- 先建立 Pro 模型的质量、成本、响应时间和用户行为基线。
- 避免将模型质量问题、Prompt 问题和产品问题混在一起。
- 等积累真实数据后，再对低风险任务进行系统性的 Pro/Flash 对照测试。

后续可优先研究的 Flash 候选任务：

- 会话标题生成
- 社区好感度评估
- 社区用户画像更新
- 社区历史摘要
- 普通社区闲聊
- 心情分析报告
- 单份测评 AI 解读
- 多份历史测评综合分析

Flash 模型只有在输出质量、结构化成功率、响应时间和用户行为均无明显下降时才允许替换 Pro。

## 5. 当前成本基线

2026 年 7 月 13 日起，上游 API 成本条件已经发生显著变化，旧版成本基线不再用于定价判断。

正式上线前需要使用新上游 API 完成一轮实测，重新记录：

- 四项功能的单次平均成本与 P95 成本。
- 缓存命中和缓存失效时的成本差异。
- 社区后台任务的每回合摊销成本。
- 三档会员额度全部用满时的理论成本。
- 各加量包全部用满时的理论成本。
- 服务器、支付、图片生成、重试与运营成本。

在新成本数据稳定前，当前价格与额度作为首发方案执行，并继续保留单用户和系统级预算预警。

- 免费用户购买加量包后转会员的比例

- 各加量包额度使用率、到期未使用比例和模型成本
- 免费用户各项额度使用率与免费转付费率

## 7. 后端额度与滥用风控

所有额度限制都必须由后端执行。前端的输入长度、剩余额度和按钮状态只用于改善体验，不能作为安全边界。

### 7.1 AI 接口访问原则

- 心情树洞、心灵社区、心情分析和 AI 测评分析接口必须要求有效登录身份。
- 前端只能提交业务参数，不允许直接提交模型名、系统 Prompt、完整 messages 数组、最大输出 Token 等模型控制参数。
- HEPAI API Key 只保存在后端，不得出现在小程序代码、接口响应、日志前端字段或静态资源中。
- 后端根据用户身份读取会员套餐、剩余额度和风控状态，不信任前端传入的套餐或额度数据。
- 每次请求生成唯一请求 ID，用于防止重复提交、网络重试造成重复调用和重复扣费。

### 7.2 输入长度限制

心情树洞和心灵社区首期采用以下默认限制，具体数值通过后端环境变量配置：

```text
单条用户消息最大字符数：500
单条用户消息最大 UTF-8 字节数：2000
单条用户消息最大输入 Token：1024
单次模型请求总输入 Token：32000
单次模型最大输出 Token：1500
```

处理顺序：

1. 反向代理或 Web 服务器先限制请求体大小，拒绝明显超大的 HTTP 请求。
2. 后端校验字符数和 UTF-8 字节数，防止用户绕过小程序直接调用 API。
3. 后端使用与当前模型兼容的 Token 统计器计算输入 Token。
4. 单条用户消息超过限制时，直接拒绝本次请求，不调用模型、不保存为正常消息、不扣除额度。
5. 返回统一错误码，例如 `INPUT_TOO_LARGE`，前端提示“本次输入内容过长，请精简后重试”。

用户当前发送的消息不应被静默截断，否则可能改变原意。只有模型历史上下文允许在后端进行预算裁剪：

- 始终保留系统 Prompt、安全规则、用户当前消息和最近对话。
- 优先删除最旧且已经进入摘要的历史消息。
- 社区优先使用已有历史摘要和用户画像代替完整旧对话。
- 树洞在上下文过长时保留近期对话，并对更早内容生成或读取摘要。
- 裁剪后仍超过总输入 Token 上限时，拒绝调用并记录风险事件。

### 7.3 输出与模型成本限制

- 所有 AI 接口由后端固定最大输出 Token，客户端不得覆盖。
- 对话、分析和测评使用不同的输出 Token 上限，避免普通聊天被诱导生成超长文章。
- 模型返回异常超长内容时，只保存通过后端长度和结构校验的结果。
- 设置单用户每日、每月人民币成本预警线，超过预警线后进入观察或限流状态。
- 设置系统级每日和每月模型预算预警线，发生异常增长时可以暂停免费额度调用，付费用户优先保障。

### 7.4 免费额度防刷

免费额度除了每月树洞 100 次、社区 100 次、心情分析 4 次和 AI 测评分析 4 次外，还需要以下风控：

- 微信登录用户 ID 作为主额度主体。
- 同时记录脱敏 IP、设备标识、登录账号和请求特征，用于识别批量账号或同设备多账号刷取。
- 对同一用户、同一 IP 和同一设备设置可配置的分钟级、小时级请求频率限制。
- 同一用户同一功能只允许一个 AI 生成请求并发执行，避免并发绕过额度。
- 新账号短时间内连续耗尽多个 AI 功能额度时，标记为异常行为并降低请求频率。
- 同一 IP 或设备批量创建、切换账号并持续消耗免费额度时，触发临时封禁或人工复核。
- 风控触发时返回统一错误，不向客户端暴露具体阈值和检测规则。

首期建议使用 Redis 实现短周期频率限制、并发锁和额度预占，数据库保存最终权益余额、消费流水和风险记录。

### 7.5 额度扣减事务

为防止请求失败、重复提交和并发请求导致错误扣费，AI 调用采用“预占、确认、释放”流程：

1. 后端完成身份、套餐、额度、输入长度和风控检查。
2. 原子预占 1 次对应功能额度，并记录请求 ID。
3. 调用模型并校验返回结果。
4. 生成成功且结果成功保存后，确认本次额度消费。
5. 模型失败、内容安全拦截、返回无法解析或保存失败时，释放预占额度。
6. 相同请求 ID 再次提交时返回已有结果或已有状态，不重复调用模型和扣除额度。

额度流水至少记录：

- 用户 ID、套餐和功能类型
- 请求 ID 与调用时间
- 调用前后剩余额度
- 预占、成功、释放或拒绝状态
- 输入字符数、字节数和 Token 数
- 总输入 Token、输出 Token 和实际成本
- 风控结果与拒绝原因代码
- 模型调用和结果保存是否成功

### 7.6 异常行为处置

按照风险程度依次处理：

1. 提醒用户输入过长或操作过快。
2. 对单一功能进行短时间限流。
3. 暂停免费 AI 权益，保留基础记录和基础测评功能。
4. 暂停全部 AI 调用并进入人工复核。
5. 对明确的自动化攻击、批量账号或接口滥用进行账号、设备和 IP 联合封禁。

所有风控拒绝均不扣除用户额度。风控系统不得影响用户查看已有记录、日历、历史报告和基础测评结果。

### 7.7 上线前最低安全要求

以下项目属于 VIP 和免费额度上线前的 P0，不完成则不应开放正式 AI 付费接口：

- 后端完成会员状态、免费额度和付费额度校验。
- 后端请求模型增加字符数、字节数和 Token 上限。
- 反向代理或应用服务器增加请求体大小限制。
- 所有模型调用增加服务端最大输出 Token。
- Redis 增加用户级频率限制、并发锁和额度预占。
- 数据库增加额度余额、额度流水和请求 ID 唯一约束。
- 数据库增加加量包订单、剩余额度、购买时间和到期时间记录。
- 模型成功且结果保存成功后才确认扣次，失败自动释放预占额度。
- AI 接口增加统一错误码，至少覆盖额度不足、输入过长、频率过高、请求重复、风控拒绝和模型失败。
- HEPAI Key 完成服务端环境变量管理和泄漏检查。
- 增加单用户和系统级 Token、人民币成本监控与告警。

当前前端与后端均已将树洞单条消息限制为 500 字，社区限制为 200 字。后端同时校验 UTF-8 字节数和估算 Token，并将树洞总对话上下文裁剪到 32000 Token 预算内。社区完整动态 Prompt 的精确 Token 预算仍需在接入模型兼容 Tokenizer 后继续收紧。

### 7.8 会员与加量包支付安全

- 套餐价格、加量包价格、SKU 和到账额度全部由后端配置，前端只提交后端签发的商品标识。
- 后端创建支付订单时再次读取商品价格，不接受客户端传入的最终支付金额或到账次数。
- 微信支付回调必须完成签名验证、订单金额校验、商户订单号校验和支付状态校验。
- 支付订单号具有唯一约束，同一支付回调重复到达时只能入账一次。
- 只有订单状态从未支付成功变为已支付时，才创建会员权益或加量包额度。
- 加量包到账时写入购买时间、到期时间、原始额度和剩余额度，并生成权益流水。
- 支付成功但权益入账失败时进入可重试补偿队列，不允许依赖前端再次发起支付。
- 退款时根据订单、已使用额度和退款规则处理剩余权益，具体退款折算方式在支付开发前定稿。
- 前端展示的支付成功状态必须以后端订单查询结果为准，不能仅以客户端支付回调为准。

## 8. 首发推广规则

首发推广需要在上线前明确：

- 首发体验价暂不设置公开结束日期或人数上限，根据实际推广效果、付费人数和模型成本决定何时结束。
- 后台仍需设置单月模型成本预警线，避免推广期间发生不可控支出。
- 准备恢复标准价格时，再正式确定生效日期和最终标准价格。
- 首发体验价用户至少享有 3 个月价格保护期，具体起算方式在恢复标准价格前确认。
- 价格调整前需要通过小程序页面或其他可达方式提前通知用户。

首发体验价页面不应使用没有实际销售依据的划线原价。计划标准价在正式执行前仍可根据推广数据调整。

## 9. 已确认的额度规则

- 免费用户额度按自然月重置。
- 付费用户额度按购买周期重置。
- 免费与付费剩余额度均不结转。
- 只有模型成功生成且结果成功保存时才扣除额度。
- 模型失败、系统异常、内容安全拦截、输入超限和风控拒绝均不扣除额度。
- 缓存命中和查看已有报告不重复扣除额度。
- 免费用户和会员用户均可购买单功能加量包。
- 加量包自购买成功之日起 90 天内有效，不随月度或会员周期重置。
- 用户没有有效会员时，仍可使用有效期内的已购加量包。
- 同一功能每 30 天最多购买 5 个加量包。
- 首发体验价暂不设置公开结束时间。
- 恢复标准价格时，首发用户至少享有 3 个月价格保护期。

## 10. 待确认规则

以下规则尚未正式定稿，需要在支付系统开发前确认：

- 会员升级时剩余权益如何折算
- 退款后已使用权益如何处理
- 是否提供年度会员
- 首发价格保护期的具体起算时间
- 各 AI 功能最终输入、总上下文和输出 Token 上限

## 11. 当前推荐原则

- 相知会员作为首期主推套餐。
- 不宣传“无限对话”，所有套餐均使用明确月度额度。
- 免费用户每月持续获得少量完整体验额度，而不是只提供一次性试用。
- 免费用户可以按需购买单功能加量包，不强制先开通会员。
- 额度不足时优先展示会员升级，再提供单功能加量包。
- 首发阶段使用“首发体验价”文案，不宣传尚未真实执行的划线原价或五折。
- 首期以用户体验和付费验证为优先目标。
- 在真实数据不足前，不根据理论价格过度优化模型。
- 所有降本调整必须经过质量和用户行为验证。
- 所有配额、输入长度、Token 和频率限制必须由后端执行，不能依赖前端。
